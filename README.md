# Практическая №4 — простая сетевая 3D-демонстрация

Одна сцена, плоская площадка, стена и капсулы игроков. При запуске — две кнопки: **Сервер** и **Клиент**. Сервер работает в режиме **Listen Server / Host**: он же первый игрок. Клиент — второй игрок в отдельном окне.

**Unity 6000.5.0b2**, Netcode for GameObjects 2.13.3, Unity Transport 6.5.0, Input System 1.19.0, URP 17.5.0. Никакие объекты и компоненты вручную добавлять не нужно.

Методичка требует **Unreal Engine, ACharacter и CharacterMovementComponent**. Здесь по запросу сделана **адаптация на Unity**: механизмы server authority, prediction, saved moves и reconciliation реализованы в C#. Требования к конкретному движку и штатному компоненту Unreal этим не выполняются; возможность сдачи Unity-версии нужно согласовать с преподавателем.

## Быстро запустить готовое приложение на Mac

1. Дважды нажми **`Запустить демо.command`** в корне проекта. Откроются **два окна одной программы**, оба с меню.
2. В первом нажми **«Сервер»**. Появится оранжевая капсула.
3. Во втором нажми **«Клиент»**. Появится синяя капсула. В каждом окне видны оба игрока.
4. Кликни по нужному окну и ходи клавишами **WASD**. Управляется только его персонаж.

Само приложение: `Builds/PredictionLab.app`. Для второго экземпляра можно выполнить `open -n Builds/PredictionLab.app` из корня проекта.

Для переноса исходников подготовлен `Builds/Practical4-Unity-Source.zip`: в нём проект, инструкция и материалы проверки без кэша Unity и готового приложения. После распаковки открой папку Game_PRMICSS в Unity и выполни сборку через меню Practical 4.

## Запустить через Unity

1. Unity Hub → **Add / Add project from disk** → эта папка → открыть в **6000.5.0b2**.
2. В Project открыть **`Assets/Scenes/Demo.unity`** двойным щелчком.
3. Нажать **Play**, перейти на вкладку **Game**, нажать **«Сервер»**.
4. Открыть `Builds/PredictionLab.app` и нажать **«Клиент»**.
5. Кликнуть по Game или окну сборки перед вводом с клавиатуры. Для показа удобно поставить окна рядом.

Если менял код, пересобери приложение: верхнее меню Unity → **Practical 4 → Build macOS and validate simulation**. Проверка симуляции запускается перед сборкой автоматически. Обычный Build Profiles также работает: в списке уже одна сцена Demo.

Для другого компьютера: скопировать подходящую сборку, в настройках клиента указать IP компьютера сервера; одинаковый UDP-порт **7777** в обоих окнах. По умолчанию **127.0.0.1** — два окна на одном компьютере. Готовая сборка проверена только на macOS; для Windows нужна отдельная сборка через Unity Build Profiles.

## Управление

| Клавиша | Действие |
| --- | --- |
| WASD / стрелки | Ходить и поворачиваться |
| Shift / пробел | Рывок на 4 единицы, кулдаун 3 секунды |
| P или кнопка вверху | Включить / выключить локальное предсказание |
| F | Намеренно ошибочный локальный рывок для показа коррекции |
| Tab | Показать / скрыть ACK, сохранённые вводы, замеры и число коррекций |
| Esc / «Меню» | Отключиться и вернуться к выбору роли |

Метка на капсуле показывает направление поворота. Через стену и границы площадки ходить и делать обычный рывок нельзя. Коллизии проверяет общая симуляция, не Unity Rigidbody.

## Показать работу за 3–5 минут

### 1. Два игрока и серверная проверка

Запусти сервер и клиент без задержки. Походи в обоих окнах, покажи, что чужой персонаж тоже двигается. Сделай рывок **Shift**, сразу нажми ещё раз: сервер откажет из-за кулдауна. Наезд на стену также запрещён.

### 2. Задержка без предсказания

Выйди в меню **в обоих окнах**. Открой **«Настройки подключения и задержки»**, выбери **«100 мс / 0%» в обоих окнах**. Снова запусти сервер, затем клиент.

На **клиенте** нажми **Tab**, затем **P**, чтобы было **«предсказание ВЫКЛ»**. Нажми Shift: персонаж сдвинется только после ответа сервера. Статистика покажет задержку реакции. Рывок делай на свободном месте, после завершения кулдауна.

### 3. Та же задержка с предсказанием

На том же клиенте нажми **P**, чтобы было **«предсказание ВКЛ»**. Дождись кулдауна и нажми Shift. Теперь персонаж сдвигается сразу, а серверное подтверждение приходит позже. Сравни **«Отклик»** и **«Ответ сервера»**. Показывать разницу нужно на клиенте: у игрока сервера нет сетевого пути до своего же сервера.

### 4. Потери и серверная коррекция

Снова выйди в меню в обоих окнах. Выбери **«175 мс / 4%»** на каждой стороне, переподключись, на клиенте включи предсказание и статистику.

На клиенте в свободной части площадки:

1. Нажми **Shift** — обычный разрешённый рывок.
2. Примерно через **полсекунды** нажми **F**, пока кулдаун не закончился.
3. Синий игрок локально сделает заведомо неправильный удлинённый рывок.
4. Сервер отклонит второй рывок из-за кулдауна. Через задержку клиент вернётся к допустимому положению, счётчики **«Коррекций»** и **«Отказов»** вырастут. Можно продолжать ходить.
5. В серверном окне ошибочного телепорта не было: туда попало только проверенное состояние.

**F — разовая отладочная команда**, а не режим читов. Она портит только локальное предсказание. В сеть уходит обычный запрос рывка без координат и без флага ошибки. Профиль 175 мс делает возврат хорошо заметным.

После демонстрации верни **«Без задержки»** в меню **обоих** окон и запусти сессию заново.

## Что коротко рассказать по коду

1. **`Assets/Data/NetworkTopologyManager.cs`** — кнопка «Сервер» вызывает `StartHost`, «Клиент» — `StartClient`; сервер разрешает подключение и создаёт игрока.
2. **`Assets/Data/ServerAuthoritativeMovement.cs`**, `SendInput` — владелец считывает направление и рывок, нумерует команду, сохраняет её в `pending`. С CSP сразу симулирует её локально. RPC передаёт **ввод, а не позицию**.
3. Там же `SubmitInputServerRpc` и `FixedUpdate` — сервер проверяет владельца, номер, направление и размер очереди; обрабатывает один шаг за тик, независимо вычисляет позицию и публикует `replicated`.
4. **`Assets/Data/PredictionSimulation.cs`**, `Simulate` — одна функция для клиента и сервера: скорость, направление, кулдаун, стена и границы. Ошибочный режим F применяется только на клиенте.
5. **`ServerAuthoritativeMovement.OnSnapshot`** — получить ACK, убрать подтверждённые вводы, восстановить полное серверное состояние, повторить оставшиеся. Это **server reconciliation**.
6. Ветка `!IsOwner` в `Update` — сглаживание чужого персонажа к последнему серверному снимку.

Фраза для объяснения: **«Клиент сразу показывает предполагаемый результат ради отзывчивости, но окончательное решение принимает сервер. При ошибке клиент восстанавливает серверное состояние и повторяет ещё не подтверждённые команды. Поэтому клиент не может просто прислать желаемые координаты и телепортироваться».**
